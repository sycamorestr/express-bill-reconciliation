# 结果工作簿约定

默认另存三页：**商品异常汇总、运单明细、核对依据**。首先回答“哪个商品、多少异常单、差多少钱、是什么原因、找谁核查”，再提供逐单证据。输入文件不覆盖；聚水潭原运费完全不参与。

## 数据来源固定

先运行 `scripts/reconcile.py`。以下各页只展示本次 `result.json` 中的结果，不重新计算价格、不重新分配主原因、不自行扩大多收费集合。`products` 对应商品汇总，`details` 对应异常运单，`all_records`、`price_rules`、`rule_issues`、`input_metadata` 对应核对依据，`unidentified_records` 对应待补单号记录，`evidence` 对应快递举证明细。引擎字段 `差额` 在报告中显示为“总差额”或“核对多收金额”，字段名称变化不改变数值。

金额在 JSON 中以十进制字符串保存，写入 Excel 时转换为数值并使用两位小数格式；`null` 写为空白，不能转换成零。单号和商品编码始终写为文本。可以用简单公式汇总已给出的逐票金额以便复核，但不得以工作簿公式重新选地区、重量档或报价版本。

汇报前比对工作簿的运单集合、主原因、商品分组及金额与 JSON 完全一致；举证来源链接须与 JSON 的源工作表、原始行号、字段列映射对应。随结果保留 `manifest.json` 与 `profile-resolved.json`，便于他人复现。它们是复现附件，不增加首页列数。

## 主原因与金额口径

固定三个基础金额：`A = 快递账单收费`，`C = 按快递重量计算`，`S = 按系统重量计算`。C、S 使用同一已确定日期、地区、用户价格表和附加费规则，仅重量不同；S 使用系统实际重量，不能使用系统原运费。

- **总差额 = A − S**：用户需要解释的账单差额。
- **重量影响金额 = C − S**：双方重量导致的报价差额。
- **计价差异金额 = A − C**：即使采用快递重量，账单仍与价格表不一致的部分。
- 恒等式：**总差额 = 重量影响金额 + 计价差异金额**。分解项不能再与总差额重复累计；正负均保留，两项抵消时也保留复合异常。

“收费不同”或“运费有差额”只是结果，不能与其原因作为并列分类。每个可识别异常运单只分配一个**主原因**，其他独立检查发现作为附加事实留在明细。依次处理下表，采用第一个适用主原因；规则明确的独立检查继续完成。

| 顺序 | 适用情况 / 主原因 | 先找谁与复核动作 |
|---|---|---|
| 1 | 重复单号、商品多行无法关联等：关联待核实 | 找对应数据提供方核原始记录；需要双方资料时明确双方，禁止任选一行核价 |
| 2 | 仅快递有单 | 仓库核发货归属、出库记录及发货凭证；主差额未知 |
| 3 | 仅系统有单 | 快递核账期和账单覆盖，必要时仓库补发货凭证；主差额未知 |
| 4 | 地区口径未定：地区待确认；日期也未定时唯一归“地区和日期待确认” | 快递明确计价地区，核对双方地区原值；组合原因同时核日期，不能推断“差额由地区造成” |
| 5 | 双方日期跨版本且口径未定：日期待确认 | 快递明确计费日期及适用报价版本 |
| 6 | 价格规则缺失/冲突、重量边界未定等：报价规则待确认；缺重量/收费等：资料待补 | 写明缺哪一项、由仓库还是快递补充；未知原因不得猜归重量或计价 |
| 7 | 重量影响非零，计价差异为零：重量影响运费 | 仓库先复称并核包装、件数和称重记录；确认后必要时向快递举证 |
| 8 | 重量影响为零，计价差异非零：计价不符 | 快递核报价版本、收费项目和附加费；双方重量差不能解释这笔差额 |
| 9 | 重量影响及计价差异均非零：重量＋计价差异 | 仓库核重量，快递核报价/附加费，两部分分别给金额及证据 |
| 10 | 两项均为零但跨比较区间或实际细分计价档：跨档但运费不变 | 仓库次要核对重量；无本次金额争议 |

前六类优先，原因被挡住时先解决其核价依据。依赖未知数据的金额留空；已能独立算出的值仍保留，并注明覆盖范围，不能以零替代未知。只有地区不同而无已确认计价口径，不能计算或声称具体“地区影响金额”。处理对象代表核查路径，不是过错认定；联系对方的消息仅作为报告建议，不自动发送。

大于 3kg 的相邻同价端点可以保留唯一的 C/S 参考金额及可确定差额，但仍归“报价规则待确认”，在“规则备注”说明边界开闭未定，不能进入举证。内部已知金额与对外可举证金额覆盖集合可能不同，举证总览必须直接取 `evidence`，不能直接复制内部正差额合计。

异常集合为重量跨比较区间或实际细分计价档、任一口径核价差异、待核价、双向单号差集的去重并集。已确认同一比较及实际计价区间且计价不变的原始重量小差忽略。空单号、精度损坏等无法识别运单的记录单列“待补单号记录”，不伪造单号混入单量。主原因分类之和等于可识别异常总单量；四项检查统计只作为独立事实，不用来相加得总单量。

## 商品异常汇总

一行对应一个完整商品编码，使用以下简短列名：

| 列名 | 口径 |
|---|---|
| 商品编码 | 系统原始完整编码；组合装、中文和 `*` 原样保留，不拆分计费 |
| 异常总单量 | 本商品异常集合内的去重运单数 |
| 总差额 | 已知 A − S 的净差 |
| 账单偏高金额 | 已知 A − S 的正差额合计 |
| 账单偏低金额 | 已知 A − S 的负差额绝对值合计 |
| 异常原因（单量） | 所有互斥主原因及数量，按需换行，如“重量影响运费 12；计价不符 3” |
| 找谁处理 | 汇集本商品全部待处理对象，显示仓库、快递或仓库＋快递 |
| 核查重点 | 与实际原因对应的简短动作，如“复称包装；核附加费” |

首页不铺开 A、C、S 和金额分解列。净差、偏高金额、偏低金额均不是已确认赔偿或追回款。金额只覆盖已知总差额的运单：部分未知时标出未知单量，全组未知则金额列全部留空。

- 每商品列全主原因及单量，**原因单量之和 = 异常总单量**。不能只显示最大原因，或漏掉另一方的核查任务。明细中的独立检查标签不再算一遍。
- 所有异常运单关联系统商品编码、商品件数。系统记录存在但编码为空，归“商品编码缺失”；仅快递有单无法关联商品，归“仅快递有单·商品待关联”，两者分开。仅系统有单仍按其商品编码汇总。
- 同票多个商品不能逐商品重复累计整票运费。保留来源完整组合编码作为一组；多行且不能确定唯一组合时归“商品关联待核实”，保留源行对应关系，不强拆数量或金额。
- 商品按账单偏高金额、异常总单量降序，商品编码用于稳定排序。链接到该商品运单明细，明细采用相同商品顺序。
- 页首仅保留异常总单量、涉及商品组数、账单偏高金额、未知差额单量等必要指标，以及一句金额口径。缺编码/待关联组不冒充已识别商品数；未知差额单量不是另加的一类异常。

## 运单明细

每个可识别运单一行。主视图展示**商品编码、物流单号、主原因、先找谁、快递重量kg、系统重量kg、快递账单收费、按系统重量计算、总差额、下一步**。具体数量、C 及分解金额可放后列或核对依据，保留清楚的定位入口。既能从商品汇总下钻，也能按单号、原因或处理对象筛选。

| 字段组 | 内容 |
|---|---|
| 商品与单号 | 完整商品编码、商品件数、匹配结果、编码/数量缺失说明、快递/系统源行 |
| 原因与行动 | 唯一主原因、首找对象、后续需要的对象、具体复核动作；处理路径可写“先仓库复称，再向快递举证” |
| 重量事实 | 双方重量、重量差异、双方比较区间与实际计价档、重量核对结果 |
| 收费事实 | A、C、S、总差额、重量影响金额、计价差异金额、各项核价状态及未知原因 |
| 附加事实 | 地区原值冲突、跨档等独立检查发现，不能重复计入主原因数量 |

金额列统一名称：**快递账单收费、按快递重量计算、按系统重量计算、总差额、重量影响金额、计价差异金额**。后两套计算是参考值，不代表已确认最终应付额。“计价不符”表示账单与明确价表存在差异，复核报价及附加费后才能确认是否收错。重量影响也不自动证明任一方称重错误。

仅某方有单不能直接称漏单；地区、日期或其他规则待确认必须说明具体缺口，不能把金额空白解释成一致。不增加聚水潭原运费比较列、总额或验证结果，输入字段名称保持原样。

## 核对依据

集中放四项完整检查、使用规则、价格表问题及逐单计算证据；次要字段可折叠，首页不重复长说明。

- **单号：** 双方记录行数、去重数、交集、双向差集、空值、精度疑点及重复冲突；不能把未解决多行关联展开成笛卡尔积。
- **重量：** 原始重量比较、六档比较、>3kg 实际细分档、忽略的同档小差；商品编码缺失和件数缺失分别统计。
- **价格：** A、C、S 和三种差额，覆盖单量、核价状态及金额来源；A − S = (C − S) + (A − C)。两套核价分别列一致、差异、未核价统计；相同覆盖集合才能求差。
- **价格表：** 报价自身缺漏/疑点，以及每票是否唯一匹配日期、地区、重量和附加费。没有合同不能宣称报价与合同一致。

每票保留源文件、工作表、行号、双方日期/地区原值、采用口径、版本、实际重量档、报价单元格、附加费条件及核价状态。针对主原因给具体复核动作和所需证据：仓库核实商品件数、包装后的复称及称重记录；快递核其计费重量、地区、日期、报价或附加费依据。

价格规则清单保留规则 ID、源单元格、原文、生效期、地区范围、重量边界、计价类型、价格/首续重参数、附加费及明确/待确认状态。疑点写明证据、影响范围、受影响运单数及需确认规则。未影响样本的报价疑点仍列出，不捏造异常运单或金额。

核对说明简记本次输入、期间、单位、字段映射、日期地区口径、重量边界、舍入及用户补充规则；明确聚水潭原运费不参与核对。来源只保留必要定位，不粘贴内部环境或调试命令。

## 快递多收费举证模式（按需）

用户要求单独生成供快递复核的多收费举证表时采用本模式，不替代默认内部三页报告，也不改变四项核对范围。另存快递原账单工作簿的副本，**原账单页保留原名称、内容、公式和格式**，新增下列页；不要覆盖任何输入文件，也不要自动向快递发送消息或文件。

| 新增页 | 内容 |
|---|---|
| 多收总览 | 纳入的去重单量、核对多收金额，三类原因各自单量和金额、简短口径及跳转入口 |
| 计价不符 | `C − S = 0` 且 `A − C > 0`：按快递重量核价仍高于价表，请核报价版本、收费项目和附加费依据 |
| 重量影响 | `C − S > 0` 且 `A − C = 0`：双方重量可解释全部差额，请提供计费称重记录并核实系统重量 |
| 重量＋计价 | `C − S ≠ 0` 且 `A − C ≠ 0`，且总差为正：分别展示重量影响与计价差异，请同时核称重和收费依据 |
| 价格表 | 附用户原价格表所有有实际内容的工作表，保留完整版本、地区、重量档、合并单元格、备注、公式与格式；多张有内容页可用清晰名称分别附入 |
| 聚水潭系统账单 | 附完整原系统账单页，保留全部原始字段、记录、内容、公式和格式；原运费列随原页保留但不参与计算、验证或推断，便于核查重量、地址、商品、件数及发货日期 |

**筛选与汇总：** 仅纳入 A、C、S 可确定、单号关联明确、报价日期/地区/规则完整，且已按本次舍入规则算出的 `A − S > 0` 的运单。总差为零、负差、未知差额、地区/日期待核价、缺单或关联未解决记录均不进入举证明细和多收合计。每票只进一类，跨运单不得以少收冲抵多收。组合原因中的分解项可为负，必须保留符号解释同一票的总差，不能只截取正分解项夸大金额。原账单页自然仍保留全部源记录，不能因其含少收记录而删除源行。

**逐票证据：** 单号、商品编码与件数、快递账单收费 A、按系统重量计算 S、核对多收金额 `A − S`、双方重量、按快递重量计算 C、重量影响金额 `C − S`、计价差异金额 `A − C`、采用日期及地区、系统原始地址和发货日期、价表版本、双方实际重量档、对应价表单元格、原账单工作表/行号、系统源行，以及请对方核查的具体事项。单号可链接原账单行，报价单元格可链接本工作簿附入的价格表。系统重量、系统地址和系统源行必须链接附入系统账单中实际单号对应的行或单元格，商品编码、件数、发货日期也可链接其源单元格；不能用明细排序后的行号代替原系统源行。按多收金额或商品排序便于处理，首页不重复展开全部证据列；详细列可分组折叠，明细应可筛选。

**对外表述：** 金额列用“核对多收金额”，页首简记“快递账单收费减去按系统重量和所附价格表重算金额；重量相关差额需核实称重，最终按双方确认结果处理”。该金额不是已确认追回款。仅用已确定地区口径计算；不得把待确认地区直接归为“地区导致多收”。聚水潭原运费仅为保留原系统账单而存在，不作为计算证据，也不参与金额或一致性验证。

**原件与价表保真：** 将原价格表完整附入，不仅摘录本次命中的价目；完全空白且无备注等实际内容的工作表可省略。示例三个日期块须全部保留，不能只附一个版本。原系统账单完整附入，不只摘录异常单；保留原字段和原始行次，明确附入页名与原页名的对应关系。源账单有公式时保留公式及可靠计算显示值，不能将公式误写为文本或让原收费显示成空白。复制前后核对原快递账单名称、行列、值、公式、格式，系统账单字段、记录、内容和格式，以及价格表数值、公式、合并范围、日期标题、备注、行列尺寸；对系统原运费仅做原件保真核验，不做业务金额或一致性校验。另存后复核可读，并检查所有系统源链接目标行单号与举证明细单号一致，不得跳到另一票。

**交付核验：** 三类去重单量之和等于总览单量，三类金额合计等于总览核对多收金额，明细每票 `A − S > 0`，且 `A − S = (C − S) + (A − C)`。检查不存在重复运单、负差混入、未知核价被当成零，以及源账单/价表被改写。只将本次实际计算的数量与金额写入结果，不复用历史示例数字。

## 默认内部报告交付检查

- 商品分组完整覆盖异常集合，每个可识别运单只计一次；全表与每商品均满足主原因单量之和 = 异常总单量。无法识别单号的记录另列。
- 总差额 = 账单偏高金额 − 账单偏低金额，与明细 A − S 的已知值一致。可分解的每票及相同覆盖集合满足总差额 = 重量影响金额 + 计价差异金额，包含两项反向抵消情况。未知金额留空。
- 每商品“找谁处理”覆盖其全部明细需要的处理对象。分类不明确的记录保留待核原因，不能强行归责。
- 表头筛选与冻结适用；金额和重量为数值，单号和商品编码为文本。颜色仅辅助区分，结论同时有文字。
- 保存后打开复核；首页能直接回答“哪个商品、多少异常单、多少钱、什么原因、找谁”，明细可找到证据和下一步。交付说明简短，不重复表内长说明。
